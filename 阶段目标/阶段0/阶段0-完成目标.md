## 一、本阶段总目标

学完本阶段后，你应该能在自己的电脑上独立完成这条链路：

**新建项目文件夹 → 写 Python 脚本 → 运行 → 遇到报错会读并修复 → 用虚拟环境管理依赖**

这是所有后续阶段的地基，目标不是"学会很多"，而是**把环境彻底搞顺**。之后每个阶段的项目都在这个环境上跑。

## 二、需要掌握的内容（3 个知识点）

✅ **掌握标准**

- 能解释 `python --version` 输出的含义；
- 能用 `python hello.py` 运行脚本文件；
- 能在 REPL 里逐行输入代码并立刻看到结果；
- 遇到"找不到 python 命令"能独立排查 PATH 问题。

☑️ **检查清单**

- [ ] 已安装 Python 3.12+（推荐 3.14）
- [ ] 安装时勾选了 "Add python.exe to PATH"
- [ ] `python --version` 能输出版本号
- [ ] 用记事本/编辑器写了 `hello.py` 并用命令行成功运行

## 三、需要完成的任务（4 个小练习）

> 每个任务做完都要**保留代码**，建议建一个 `E:\学习\Python\阶段目标\阶段0代码` 文件夹存放。

### 任务 1：Hello World（中文版）

**做什么**：新建 `hello.py`，输出两行内容：一行英文 Hello，一行你自己的名字。

**参考步骤**：

1. 新建文件夹 `hello_project`，用 VS Code 打开；
2. 新建文件 `hello.py`，写入：

```python
print("Hello, World!")
print("你好，我是 [你的名字]，开始学 Python！")
```

3. 保存（务必是 UTF-8 编码），点击 ▶ 运行。

**验收标准**：终端里正确显示两行输出；中英文都不乱码；你能向别人演示"脚本是怎么运行的"。

### 任务 2：REPL 计算器练习

**做什么**：在交互式命令行里完成一串操作，体会"逐行执行"。

**参考步骤**：

1. 命令行输入 `python` 进入 REPL（提示符变成 `>>>`）；
2. 依次输入并观察结果：

```python
2 + 3 * 4
10 / 3
10 // 3
2 ** 10
name = "Python"
name + " 真好玩"
len(name)
```

3. 按 Ctrl+Z 回车（或 `exit()`）退出。

**验收标准**：每个表达式的结果都能说对；能解释 `10 / 3` 与 `10 // 3` 结果为什么不同；知道 `>>>` 提示符意味着你在 REPL 里。

### 任务 3：调试初体验

**做什么**：故意制造一个错误，学会"读报错修 bug"，再用断点看变量。

**参考步骤**：

1. 新建 `bug.py`，写入：

```python
name = "小明"
age = 18
print("你好，" + name + "，今年" + age + "岁")
```

2. 运行，观察报错。Traceback 最后一行会告诉你是 `TypeError` 以及具体行号；
3. 思考：字符串和整数能不能用 `+` 拼接？修复它（提示：`str(age)` 或 f-string）；
4. 修复后再在 `print` 那一行左侧点红点，用调试模式运行，看 `name` / `age` 的值。

**验收标准**：能指着 Traceback 说出"错误类型 + 出错行号"；修复后正常运行；能用断点看到变量当前的值。

### 任务 4：虚拟环境实战

**做什么**：为任务 1 的项目创建独立虚拟环境，安装一个第三方包并真正用上它。

**参考步骤（PowerShell）**：

```powershell
cd E:\学习\Python\阶段目标\阶段0代码\hello_project
python -m venv .venv
.venv\Scripts\Activate.ps1
```

> 如果激活时报"禁止运行脚本"错误，先执行一次：
> `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`

激活后（命令行前面出现 `(.venv)`）：

```powershell
pip install requests
pip list
```

写一个 `check_web.py` 测试这个包：

```python
import requests

resp = requests.get("https://www.python.org")
print("网页状态码：", resp.status_code)
print("网页标题：", resp.headers.get("Content-Type"))
```

运行成功后，练习卸载：

```powershell
pip uninstall requests -y
deactivate
```

**验收标准**：`(.venv)` 出现和消失你都知道原因；`pip list` 里能看到/看不到 requests；能解释"为什么这个包没有装到全局"；`deactivate` 后 `python` 还能用（因为用的是系统 Python）。

## 四、自测题（能独立回答 = 过关）

1. 什么是"解释器"？Python 的 `.py` 文件是怎么运行的？
2. REPL 和运行脚本文件有什么区别？分别在什么场景用？
3. 终端提示"python 不是内部或外部命令"，最可能的原因是什么？怎么解决？
4. 虚拟环境解决什么问题？为什么每个项目都要有独立的虚拟环境？
5. `.venv` 文件夹为什么不能删？为什么不建议提交到 Git？
6. `pip install requests` 把包装到了哪里？怎么确认装没装上？
7. Traceback（报错回溯）应该怎么读？最后一行代表什么？
8. 为什么 `"a" + 1` 会报错？把数字转成字符串有哪几种写法？
9. UTF-8 编码是什么？为什么写中文要保证文件是 UTF-8？
10. 如果 VS Code 点运行没反应，你会按什么顺序排查？（提示：解释器选对了吗？）

**参考答案（简短）**

1. 解释器逐行读代码并执行，`.py` 文件由 `python` 命令交给解释器运行；
2. REPL 逐行即时执行，适合试验；脚本文件一次性跑完，适合正式程序；
3. 没勾 PATH 或没重开终端；重新安装时勾选 "Add python.exe to PATH" 或手动添加环境变量；
4. 避免不同项目需要的包版本互相冲突；环境相互隔离、可复现；
5. 删了依赖就没了、项目跑不起来；它体积大且可由 `requirements.txt` 重建，所以不提交；
6. 装进当前激活的虚拟环境的 site-packages；用 `pip list` 查看；
7. 从下往上读，最后一行是"错误类型：错误信息 + 出错文件和行号"；
8. 类型不同不能直接拼接；`str(1)`、f-string、`format()` 都可以；
9. 统一的字符编码标准；文件编码和运行环境编码不一致就会乱码；
10. 先看右下角是否选择了正确的 Python 解释器，再看终端报错信息。

## 六、Windows 常见坑速查

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `python` 不是内部或外部命令 | 安装时没勾 PATH | 重装并勾选 "Add python.exe to PATH"，重开终端 |
| `py` 能用但 `python` 不行 | 只有 py 启动器 | 直接用 `py`，或安装时勾 PATH |
| 激活脚本报"禁止运行脚本" | PowerShell 执行策略限制 | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| 终端提示符没有 `(.venv)` | 没激活或激活失败 | 检查是否在项目目录，重新执行激活命令 |
| 中文输出乱码 | 文件编码不是 UTF-8 | 保存时选择 UTF-8 编码 |
| VS Code 运行按钮是灰色的 | 没装 Python 扩展或没选解释器 | 装微软官方 Python 扩展，右下角选择解释器 |
